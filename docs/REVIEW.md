# 项目检查与更新记录（2026-10-20）

这次保留工作区已有修改，检查并补全 Claude Desktop 切换、本地额度、账号库和邮箱验证流程。

## 已修复和补充

- Desktop 刷新不再误入 API Key 分支；支持 Chromium 明文 / zstd 额度缓存和新版用量历史，保留真实记录时间，过期窗口不显示为 0%。
- Desktop 的退出、备份、启动、删除共用 Python / Rust 跨进程锁。进程检查失败不当作已退出，核对目标目录启动后才记录成功，失败尝试恢复原目录。
- 登录文件在客户端正常退出后备份，覆盖新版 OAuth 缓存和 Network/Cookies 日志。正在使用或无法确认的目录不能被移走。
- 界面区分“上次打开”与实时登录状态；全局防重复切换，缓存和历史额度显示来源及时间。
- 新增 SQLite 账号库：主密码派生密钥，密码和邮箱授权以 AES-GCM 加密保存；默认隐藏秘密，明确操作才显示或复制。
- Gmail / Google Workspace、Outlook / Hotmail / Microsoft 365 支持只读 OAuth 接入，企业邮箱支持 TLS IMAP。授权后核对邮箱归属，刷新和修改条目互斥。
- 自动读取近期 Claude 登录邮件、提取验证码和官方验证链接。不会读取链接预览或发送、删除、标记已读邮件；绑定网页账号使用独立窗口，绑定 Desktop 验证时保持原客户端运行。
- 自动识别 Desktop 邮箱时核对当前 UUID 与身份缓存，避免把旧账号的邮箱导入另一个条目。

## 仍有的边界和后续工作

1. **真实登录验收**：自动化使用临时库和模拟 API / IMAP。没有连接用户真实邮箱，也没有执行真实双账号切换；Google / Microsoft 的应用注册、管理员授权和具体客户端版本仍需实际配置后验收。
2. **首次授权**：Gmail / Outlook 需要用户自己的桌面 OAuth 应用配置及首次授权。企业 IMAP 需要服务器、TLS 端口和可用的应用专用密码。保存普通账号密码不会替代这些服务的授权要求。
3. **额度实时性**：Desktop 数据来自客户端本地记录。关闭或长期未使用的配置可能只有旧快照，工具读取不会向服务端强制更新额度；客户端用量页写入新记录后才能读取更新。
4. **平台兼容**：Windows Store / MSIX 的自动发现与启动尚未完整支持；Linux 仅适配部分第三方封装。macOS 也需要针对后续 Claude 更新继续验证启动参数和本地格式。
5. **既有凭据存储**：新账号密码与邮箱令牌加密保存；既有 Claude Code / 网页凭据仍沿用 `secrets/*.json` 及其文件权限，尚未迁移进加密账号库。Desktop 自己的加密数据仍由 Claude 管理。
6. **依赖维护**：当前 IMAP 依赖链中的 `imap-proto 0.10.2` 有 Cargo 的未来 Rust 兼容提示，当前构建及测试通过；后续应替换或升级到兼容的新版本。
7. **认证范围**：收信和提取验证信息可以自动进行，验证链接由用户明确打开。Claude 的首次登录、回跳、Google 登录和多因素验证仍遵循其原有流程；各官方应用的登录态不自动互相转换。
